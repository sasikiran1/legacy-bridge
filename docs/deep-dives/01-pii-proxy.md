# Keeping PII out of model calls with a reversible tokenization proxy

An agent that works on a member-services portal reads names, SSNs, bank accounts and addresses on every page. The model that decides what to click doesn't need any of them as values. It needs to know that a field holds a person's name, and that the name typed later is the same one it read earlier. This write-up covers how legacy-bridge gives the model exactly that, what it measured, and where it fell short.

## The shape of the problem

Three things have to be true at once:

1. **Nothing raw leaves the host.** Groq and Gemini free tiers may log or train on inputs, and Gemini's unpaid terms forbid personal data outright. The rule applies to local models too, so there is one code path and the hosted arm needs no special case.
2. **The agent still works.** It must type the right account number into the right field, and answer "what is the claim status" with a real answer for the operator.
3. **A wrong restoration must be impossible, not just unlikely.** If the model, steered by an injected note, asks to type a stored SSN into a free-text field, the system has to refuse.

## Design

Every LLM call goes through an OpenAI-compatible proxy (`proxy/app.py`).

**Detection.** The proxy uses three sources:
- Presidio's pattern recognizers
- a GLiNER PII model (`urchade/gliner_multi_pii-v1`)
- rules for the portal's own identifiers, such as `M1234567` or `CLM-2025-104233`

JSON with known keys (`ssn`, `bankAccount`) is tokenized by key, without guesswork. Values masked earlier in the same task are re-caught by exact match wherever they reappear. That "known values" pass matters more than any detector, for reasons below.

**Tokens.** A value becomes `[[TYPE:hex10]]`: an HMAC over the task, the type and the value (ADR 0001, ADR 0011).
- Tokens are deterministic within a task, so the same name is the same token on every page and in every recorded cassette.
- They are typed, so policy can reason about them.
- They are ASCII, because the first design used Unicode brackets that tokenizers split unpredictably.

**Vault.** Token-to-value pairs sit in Redis, AES-GCM encrypted per entry, with a per-task TTL (ADR 0002). Redis's append-only file therefore holds only ciphertext.

**Rehydration at the tool boundary** (ADR 0003). Agent state, checkpoints, traces and cassettes hold tokens only (ADR 0012). Real values come back in exactly two places:
- **In executor tool arguments,** at the moment of acting, and only where `config/pii-policy.yaml` allows that entity type in that argument.
  - A `BANK_ACCOUNT` token may go into `submitReimbursement.bankAccount`. It may not go into a note body or a URL.
  - In the browser, the policy matches the field's accessible name. Unlabeled fields receive no real values.
- **In operator-facing output,** on request, including SSE streams where a token arrives split across chunks.

**Audit.** Every mask and unmask is appended to a hash-chained log, fsynced per entry. `recover` repairs a torn final write and keeps the damaged original.

**Fail closed.** If detection, the vault or the OCR step is unavailable, the request is not forwarded (HTTP 503).

## What was measured

All figures come from committed files under `analysis/results/`.

| Measurement | Result |
|---|---|
| Canaries in recorded provider payloads, production detector | 0 of 125, per agent session and with each document isolated |
| The same with Presidio's default analyzer | 23 and 76 of 125 leaked |
| Detection micro-F1, synthetic portal text / ai4privacy English rows | 0.936 / 0.881 (Presidio default: 0.547 / 0.682) |
| Latency the proxy adds, p50 / p95, CPU detection | 259 ms / 1,596 ms |
| Prompt-token overhead on PII-dense documents | +35% |
| Readable canaries surviving screenshot redaction, real member pages | 0 of 100 |

The canary set is 125 planted values across 10 members, generated by seeded Faker. Any appearance of one outside the trust boundary is a leak. CI enforces it three ways: through the proxy with the production detector, over every committed cassette, result file and replay script, and by OCR over every stored screenshot.

## What went wrong, and what it taught

**A drifted label leaked a bank account number.**
- Under the DOM-drift scenario, the portal renames "Bank account number" to "Account no.".
- GLiNER had found the account number beside the original label, but not beside the new one. The value was not in the known-values pass either, because single-word NER spans were deliberately not propagated: a mis-tagged "Member" would otherwise be masked on every page.
- The cassette leak gate stopped the recording before it was committed.
- **Fix:** a long numeric NER span (six or more digits) is now trusted and propagated (ADR 0012, amended). The lesson is that the known-values pass is the real defense in an agent session. The detector only has to catch each value once.

**Labels were masked as values.** GLiNER tagged the label "Email" as an email address and "Street address" as an address. Plausibility rules now require an `@` for emails, a digit for street addresses and two digits for numeric types, and reject role nouns ("the user") as person names.

**Masking inside words broke pages.** Re-matching the known name "Eric" inside "generic" turned snapshot text into `ge[[PERSON:…]]`. Known values now match only at word boundaries.

**Routing numbers became phone numbers.**
- Routing numbers that start with 0 (`074255580`) were claimed by Presidio's phone recognizer. It outscored the routing-number rule, so they were masked as `PHONE_NUMBER`.
- The policy then correctly refused a phone placeholder in the `bankRouting` argument, and two reimbursements stalled.
- **Fix:** a bare nine-digit value that passes the ABA checksum is retyped as a routing number, since a US phone number has ten digits. It is retyped rather than dropped, so it stays masked even without the "routing" context word.
- The policy failing closed was correct throughout; the type label was the bug.

**Screenshots.** For the one portal page whose labels are painted on a canvas, the proxy OCRs each image and masks each line, then paints every masked value over with its token (ADR 0008).
- **First bug:** the element OCR cropped two pixels inside each box. That clipped the first letter of captions drawn at the edge, so "Claim number" read as "Slaim number" and the field policy refused the claim number. OCR now reads the whole box at 4× with a white margin.
- **Unmeasured path:** a value OCR cannot read on the raw image cannot be redacted either.

## Trade-offs worth defending

- **Latency for safety.** CPU NER costs about a second per 1,000 characters at p95. Masking is cached per task and text, because the executors mask a page for agent state and the proxy sees the same text again when it reaches the model.
- **Precision over recall in the policy.** Thresholds drop GLiNER's low-confidence hits. On ai4privacy the production configuration covers 0.926 of gold characters against 0.990 without the filter. Inside an agent session the known-values pass recovers most of that, and the canary gate is the backstop.
- **Determinism for testability.** Deterministic tokens make cassettes replayable in CI with no model. The token key is published for this synthetic dataset; with real data it would be a secret.

## Limitations

- **The canary corpus is synthetic and narrow.** Zero leaks here does not mean zero leaks on real documents.
- **GLiNER on CPU is not bit-for-bit deterministic.** Replayed requests differ from their recordings in a few borderline spans per scenario. They are served and counted, and outcomes have matched.
- **ai4privacy rows are used for evaluation only.** They are never committed. That dataset is Built with Llama.
