# Milestones

Each milestone ends with green tests, a demo command, and an interview brief (what was built, the key trade-off, and two likely interview questions with answers). Then it stops for review.

## Changes from the original spec

| Change | Reason |
|---|---|
| Python 3.14, not 3.13 | 3.13 became security-only when 3.15 shipped (2026-10-09). Presidio and Phoenix cap at `<3.15`, so 3.14 is the newest usable. |
| React SPA (Vite + TypeScript) instead of server-rendered HTML (ADR 0010) | Sasi's choice of a modern frontend. The legacy premise is kept by the public/internal API split: the SPA uses its own internal endpoints, the agent only the degraded public API. |
| Groq models are `gpt-oss-20b` / `gpt-oss-120b` | Groq's free tier no longer offers Llama chat models |
| Gemini models are the 3.x Flash and Flash-Lite lines | 2.5 models are limited to past users |
| **Local-first exploration**, plus a smaller hosted arm | Budget: 50 tasks × 7 scenarios × ~10 steps × ~4K tokens ≈ 14M tokens, against ~200K tokens/day per Groq model |
| ai4privacy dataset: eval only, with Llama attribution | Its README layers the Llama Community License over CC BY 4.0 |
| Prompt Guard 2 runs locally; Sasi requests gated access | Gated, with a personal-details form; page text must stay local |
| Rehydration policy (entity type × tool × argument) | Closes the confused-deputy path in threat model T3 |
| Phoenix as the trace backend | Self-hosted Langfuse needs ClickHouse and S3 on a laptop with 75 GB free |
| mypy strict as the type checker | The spec named no tool |
| Prices are effective-dated | Gemini Flash list prices double on 2027-01-01 |

## Experiment budget

**Two arms**, reported separately and never mixed in one average:

- **Local arm:** all ~50 tasks × 7 scenarios. Exploration uses a local Ollama text model, chosen in M3 by a bake-off on a 10-task dev subset. $0 notional; GPU-seconds reported.
- **Hosted arm:** ~10 tasks × 3 scenarios (healthy, DOM drift, injected notes), plus the 20-run hero-chart workflow, on Groq/Gemini.
  - Recorded once as cassettes, then replayed.
  - Recording is spread over days to stay within free limits. The recorder stops at 80% of the daily cap.

## M1: Portal and testbed

**Done 2026-10-21.** Deviations from the plan below:
- **Auth uses JDK PBKDF2 and an interceptor,** not Spring Security, so no unapproved dependency.
- **The Python toolchain runs in a `testbed` container** (Playwright base image plus uv), because the Windows host blocks unsigned native binaries.
- **The seed is a repeatable migration** (`R__seed_data.sql`), not `V2`.

- **Portal:**
  - Spring Boot 4.1, JPA, Flyway, Postgres 18
  - React SPA in `portal/web/`, styled as a dated intranet, built in a multi-stage Docker image and served by Spring Boot (ADR 0010)
  - members, policies, claims, reimbursements, notes
  - session login with per-user test accounts
- **Public REST API** `/api/v1/**`, documented with springdoc: some endpoints work, some return 404/410, some drift in schema.
- **Internal API** `/internal/**` for the SPA: undocumented, and not degraded by API chaos.
- **Chaos admin endpoint** (admin-token protected), with toggles:
  - API removal or deprecation per endpoint
  - schema drift
  - DOM drift: renamed IDs/labels, moved buttons, interstitial modal
  - slow responses
  - session expiry
  - CAPTCHA/MFA wall (detect-only fixture, nothing solvable)
  - poor-accessibility page
  - injected notes
- **Seed data:** generated by a Python Faker script with a fixed seed. Canaries are tagged in a sidecar file. The portal loads the fixture through Flyway, so one generator owns all PII.
- **Task suite (Python):** ~50 task definitions (Pydantic), each with:
  - a SQL post-condition check
  - a scripted Playwright oracle (no LLM)

  The oracle suite runs across the scenarios where the task is meant to be solvable.
- **Tests:** JUnit 5 + Testcontainers (portal). pytest (oracles against the Compose stack).
- **CI:** Maven build and tests, Python lint/type/test, oracle suite in Docker.
- **Demo:** `make portal-up && make oracles`
- **CI also runs** `npm ci && npm run build` for the SPA.
- **Dependency approvals needed:** Flyway starter; Faker, PyYAML, mypy, Playwright. React, Vite, TypeScript, and React Router are already approved (ADR 0010). Vitest only if needed.

## M2: PII proxy

- **Detection:** Presidio + GLiNER (`urchade/gliner_multi_pii-v1`) + custom recognizers (member ID, policy number, claim number). PII policy YAML.
- **Tokenizer** per ADR 0001. **Vault** per ADR 0002. **Rehydration** in text, tool arguments, and SSE per ADR 0003, plus the policy engine.
- **FastAPI** OpenAI-compatible `/v1/chat/completions`, streaming and non-streaming. Fails closed.
- **Audit log:** hash-chained, append-only JSONL, plus a `verify` CLI and tamper tests.
- **Leak test:** recording mock provider; assert zero canaries in outbound payloads, cassettes, traces, and results. Gates CI.
- **Hypothesis properties:** mask→unmask is exact; a token is never split by streaming; tokens are deterministic within a task and distinct across tasks.
- **PII benchmark:** regex-only / Presidio default / + GLiNER / full config. P/R/F1 per entity type on synthetic portal text (primary) and an ai4privacy subset (eval-only).
- **Proxy added latency:** p50/p95.
- **Demo:** `make proxy-demo` (masked request, streamed rehydrated answer, audit verify)
- **Dependency approvals needed:** presidio, gliner/transformers/torch, a spaCy model, FastAPI/uvicorn/sse-starlette, redis-py, cryptography.

## M3: Agent

- **LangGraph state machine:** plan → API tier → replay tier (stub until M4) → exploration → handoff. Postgres checkpointer; interrupts.
- **API tier:**
  - tools generated from the portal's OpenAPI spec, with entity-typed arguments for the rehydration policy
  - Pydantic validation of responses
  - per-endpoint circuit breakers (ADR 0004)
- **Exploration:** `@playwright/mcp` through the MCP Python SDK 2.x, driven by accessibility snapshots, with a token-budget trimmer.
- **Guardrails:**
  - domain and action allowlists
  - a post-condition check after every write
  - approval interrupts for destructive and payment-like actions
  - Prompt Guard 2 and datamarking (ADR 0009)
  - CAPTCHA detection → handoff
- **All LLM traffic goes through the proxy.** Cassettes; per-provider rate limiting; 429 fallback chain.
- **Local text model bake-off;** fills `roles.local_text` in `config/models.yaml`.
- **Demo:** `make demo-fallback` (API 404 → browser completes the task, with post-condition verified)

## M4: Cost

- **Replay:** compiler and runner, plus self-heal (ADR 0005).
- **Snapshot trimming,** raw vs. trimmed.
- **Routing** by tier.
- **Vision tier** with OCR redaction (ADR 0008).
- **Cost ledger** with notional pricing (ADR 0007).
- **Demo:** `make demo-replay` (cold run, replay at $0, DOM change, self-heal spike)

## M5: Experiments and report

- **Experiment runner:** writes `analysis/results/<run_id>/` with a manifest.
- **Metrics and bootstrap CIs** for every metric in the spec.
- **`make report` builds a static site in `docs/report/`** with the seven panels. Publishing to GitHub Pages happens only after Sasi approves.
- **Also:** Mermaid diagrams, a Grafana dashboard JSON, an asciinema/GIF of the fallback run.
- **README top section:** problem, hero chart, 3-number table, architecture diagram, Reproduce, Limitations.
- **CI regression gate:** smoke run vs. `main` on success rate and wrong-action rate.
